# Console 需求文档

- 版本：v1.0（开发前规格）
- 日期：2026-10-27
- 状态：待评审
- 关联文档：`console/docs/development.md`（开发文档）

## 1. 背景与定位

Harbor 负责评测编排：创建 trial 容器、执行 Agent、运行 verifier、保存结果。`scripts/run.sh` 负责预检、配置渲染与运行入口。Harbor view 负责轨迹查看。

当前缺少一层面向日常操作的界面：数据集维护、评分器配置、实验运行、结果分析、人工复核、失败案例回流都需要在命令行与多个工具之间手工衔接。

Console 是这层界面。它是一个薄工作台：

- 只做编排与展示，评测执行仍由 Harbor 完成。
- 不修改 Harbor 编排代码。
- 不修改 Harbor view 的信息读取逻辑，轨迹详情直接内嵌 Harbor view 页面。
- 单人本地使用，第一版不实现多人账号体系。

仓库整体开源。使用者 clone 代码库、安装 Docker、填写 `.env` 即可运行完整评测。Agent 与任务环境全部运行在本地 Docker 容器中，执行的是仓库内代码构建出的镜像。控制台随仓库分发，是这条本地链路的可视化界面，不引入独立的执行服务。平台本地数据（`console.db`、`workspace/`）不进版本库。

## 2. 术语

| 术语 | 定义 |
| --- | --- |
| Dataset | CSV 格式的任务集合。每行一个任务，包含输入、预期结果、标签、元数据、评分标准。 |
| Dataset Version | 数据集的一次保存快照。每次变更产生新版本，旧版本只读保留。 |
| Experiment | 一次实验。记录数据集版本、Scorer、Agent 参数与运行结果，创建后不可变。 |
| Rollout | Experiment 中让任务执行 Agent 批量完成任务的过程，产出 Trace。 |
| Trace | 单个任务的一次执行记录：Agent 输入、完整轨迹、输出、耗时、token 用量。 |
| Scorer | 评分器。对 Trace 打分，分 LLM judge 与 Code 评分器两类。 |
| Judge | Scorer 对 Trace 的一次评分动作，产出结构化分数与判定理由。 |
| Baseline | 被标记为基准的 Experiment，用于后续实验的回归对比。 |
| Review | 人工复核。用户对存疑 Trace 结构化打分并写备注。 |
| Loop-Assistant | 帮助评测自进化的 Agent：归类失败原因、生成改进方案、抽取案例形成新数据集草案。 |

## 3. 用户与使用场景

第一版只有一个用户角色：评测负责人（单人模式，当前登录用户即操作者，无账号管理）。

日常操作链路：

```text
准备数据集 → 选择评测对象 → 配置评分器 → 运行实验
    → 结果分析 → 人工复核 → 闭环回流 → 新一轮数据集
```

## 4. 功能需求

### FR-1 准备数据集

**目标**：上传并维护 CSV 任务集，平台保存每次变更的版本。

**CSV 字段**：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 任务唯一标识。同一数据集内不重复。 |
| `input` | 是 | 任务输入，即交给 Agent 的任务描述。 |
| `expected` | 是 | 预期结果，供 Scorer 评分参考。 |
| `tags` | 否 | 标签列表，逗号分隔。用于分组、过滤、失败模式统计。 |
| `metadata` | 否 | JSON 对象。存放难度、场景、风险等级等自定义键值。 |
| `rubric` | 否 | 评分标准文本。LLM judge 的评分依据，可覆盖数据集级默认值。 |

**功能点**：

1. 创建数据集：填写名称、说明与任务环境模板。环境模板决定 trial 的容器环境（普通任务 / esa 任务），是数据集属性，不进 CSV。
2. 上传 CSV：解析并校验字段。校验项包括表头完整、`id` 唯一、`metadata` 是合法 JSON、`input` 非空。校验失败时逐行报告错误，不写入任何数据。
3. 数据集列表：显示名称、版本数、任务数、最近变更时间。
4. 版本历史：每个版本显示版本号、变更说明、任务数、变更行摘要（新增、修改、删除的数量）。
5. 版本对比：选择两个版本，逐行展示差异（输入、预期结果、标签、元数据、评分标准）。
6. 新建版本：在当前版本基础上编辑行、上传替换 CSV、或从 Loop-Assistant 草案合并（见 FR-7）。保存时填写变更说明，产生新版本。
7. 版本只读：已保存版本不可修改，只允许从其创建新版本。
8. 数据集导出：任意版本可下载为 CSV，内容与上传时一致。

**验收标准**：

- 上传含非法行的 CSV，平台拒绝并给出行级错误，数据集版本数不变。
- 连续保存三次变更，版本历史出现三个版本，对比任意两个版本能看到行级差异。
- 下载任意版本的 CSV，与该版本上传内容一致。

### FR-2 选择评测对象

**目标**：选择任务执行 Agent 与模型，管理批量任务实验。

**说明**：评测对象是执行任务的 Agent（OpenCode、pi、Claude Code、esa runtime），不是单次 LLM 调用。Agent 以 harness 镜像形式运行在 Harbor trial 中。

**功能点**：

1. 评测对象配置页：从现有 `configs/harnesses/` 读取可用 harness，从 `configs/models/` 读取可用模型。支持查看与编辑 Agent 运行参数（如推理档位、最大轮数）。
2. 参数编辑产生新的参数版本，历史参数随 Experiment 快照保留（见 FR-4）。
3. Experiments 界面：列出所有实验。列包含名称、数据集与版本、harness、模型、Scorer、状态、总分、创建时间。
4. 实验筛选：按数据集、harness、模型、状态、标签筛选。
5. 实验状态机：

```text
草稿 → 运行中 → 已完成
         ↘ 失败（含失败原因）
草稿可编辑；进入运行中后不可修改；失败实验保留现场，可复制为新实验重跑。
评分随 rollout 在 trial 内完成，不设独立评分阶段。
```

**验收标准**：

- 评测对象配置页能看到三个 harness 与已配置模型，参数修改后生成新版本。
- Experiments 列表能按 harness 与状态筛选。

### FR-3 配置评分器

**目标**：添加 LLM judge 与 Code 评分器，用真实日志试评通过后保存。

**功能点**：

1. Scorer 列表：名称、类型、版本数、最近使用实验数。
2. LLM judge 配置：
   - 选择 judge 模型（来自 `configs/models/`，与 `.env` 密钥复用同一套机制）。
   - 编写评分提示词：输入为任务输入、预期结果、评分标准、Trace 摘要与 Agent 输出；输出为结构化 JSON（分数、判定、失败类别、理由）。
   - 分数范围配置（默认 0 到 1）。
   - 输出 schema 可查看，平台校验 judge 返回的 JSON 与 schema 一致。
3. Code 评分器配置：
   - 在线编写或上传 Python 评分脚本。
   - 函数签名约定见开发文档。输入为任务输入、预期结果、Trace；输出为分数、判定、失败类别、附加上下文。
   - 执行受控：超时上限、禁止网络访问、异常被捕获并展示。
4. 试评（dry run）：
   - 选择已有实验的 Trace（真实日志）逐条试评。无历史实验时可粘贴样例文本试评。
   - 试评执行与正式评分完全相同的评分逻辑，区别只在结果标注为试评记录，不写入正式实验数据。
   - 展示每个 Trace 的输入、Agent 输出、Scorer 输出与耗时。
5. 保存 Scorer：试评可选，保存产生不可变版本。后续修改产生新版本。
6. Scorer 版本历史：与数据集版本一致，只读保留。

**验收标准**：

- LLM judge 试评一条 Trace，能看到结构化输出（分数、判定、失败类别、理由）。
- Code 评分器脚本语法错误时，试评界面显示完整异常信息，不产生版本。
- 保存后的 Scorer 出现版本 1，再次修改保存出现版本 2，两版本都可查看。

### FR-4 运行实验

**目标**：UI 点选运行，产出包含 rollout 与 judge 的 Experiment，保存为不可变快照。

**功能点**：

1. 新建实验：选择数据集版本、评测对象（harness + 模型 + 参数版本）、Scorer 版本。可填写实验名称与备注。
2. 运行前确认页：显示完整运行计划（任务数、harness 镜像版本、模型、Scorer、预计并发）。等同 `run.sh --dry-run` 的预检结果一并展示：镜像检查、网关检查、Docker 版本检查。预检失败不允许启动。
3. 一键运行：点击运行后平台依次执行 rollout 与 judge，全程展示进度（已完成任务数、失败数、当前阶段）。
4. Rollout 执行：由 Harbor 执行。任务由数据集版本渲染生成，Agent 参数与模型来自评测对象配置。
5. 评分执行：评分在 Harbor verifier 内完成，与 workbuddy-bench 的 CompositeVerifier 形态一致。每个 trial 结束时 verifier 自动运行选定的 Scorer（Code 评分器或 LLM judge），分数随 trial 结果落盘。单条评分失败不中断整批，失败记录进实验结果。
6. 不可变快照：实验启动时固化以下内容，实验完成后只读：
   - 数据集版本号与该版本内容的哈希。
   - Scorer 版本与其配置内容。
   - Agent 参数（harness、镜像版本、模型、运行参数）。
   - 渲染后的 Harbor job 配置全文。
   - 运行命令与环境摘要（代码 git 提交号、Harbor 版本）。
   - 创建时间与操作者（单人模式下为固定值）。
7. 中止：运行中的实验可中止。已产出的 Trace 与分数保留，实验标记为已中止。
8. 失败处理：rollout 或评分发生整体性错误时，实验标记失败并记录失败原因与日志位置。

**验收标准**：

- 用含 3 个任务的数据集运行一次实验，能看到进度推进，最终状态为已完成。
- 实验详情页展示快照信息：数据集版本、Scorer 版本、harness 镜像版本、模型、job 配置全文。
- 实验完成后尝试修改实验配置，界面不允许任何修改入口。
- 中止一个运行中的实验，状态为已中止，已完成任务的结果仍可查看。

### FR-5 结果分析

**目标**：结果表看分数、Logs 定位失败、Dashboards 看分布与失败模式、基线对比。

**功能点**：

1. 结果表：每个任务一行。列包含任务 id、输入摘要、Agent 输出摘要、分数、判定、失败类别、耗时、token 用量、Review 状态。
2. 排序与过滤：按分数升序（默认定位低分）、按耗时、按 token；过滤失败判定、过滤失败类别、按标签与元数据键值过滤。
3. Logs 页：逐条 Trace 列表，点开单条进入 Trace 详情。
4. Trace 详情：
   - 平台侧展示：任务输入、预期结果、Scorer 输出（分数、判定、失败类别、理由）、元数据、Review 记录。
   - 轨迹部分内嵌 Harbor view 的 trial 页面，展示完整轨迹、工具调用、agent 日志。
   - 页面提供"标记存疑"按钮，进入 Review 队列（见 FR-6）。
5. Dashboards：
   - 分数分布直方图。
   - 按标签与元数据键分组的均分与通过率表格。
   - 失败类别分布。
   - 回归排序表：与基线对比后按分数变化排序，恶化项排前（见下条）。
   - 所有图表支持过滤条件联动（标签、失败类别、元数据）。
6. 基线对比：
   - 任意已完成实验可标记为基线。同一数据集下保留一个当前基线，不绑定数据集版本。
   - 选择当前实验与基线，展示逐任务分数变化、新增失败、修复项、整体均分变化。跨数据集版本对比时按任务 id 匹配共同任务，新增与删除的任务单独标注。
   - 回归排序按分数变化从小到大排列。
7. 导出：结果表与对比结果导出为 CSV。

**验收标准**：

- 结果表默认按分数升序，过滤失败判定后只显示失败任务。
- Trace 详情页内嵌的 Harbor view 轨迹正常展示，页面风格与平台一致。
- 标记一个实验为基线后运行第二个实验，对比页显示逐任务变化，恶化任务排在前面。

### FR-6 人工复核

**目标**：存疑 Trace 进入 Review，结构化打分加备注，多人评分可汇总（第一版单人）。

**功能点**：

1. Review 队列：从 Trace 详情标记存疑进入；显示任务摘要、Scorer 分数、标记时间。
2. 复核表单：
   - 结构化打分维度：正确性、完整性、安全性、格式符合度。每项 1 到 5 分。
   - 总体判定三档：通过、存疑、不通过。
   - 备注文本。
   - 复核表单维度可在设置中调整（增删维度、修改维度名）。
3. 汇总：实验维度汇总人工复核结果，结果表增加人工复核列，Dashboards 支持按人工判定分组。
4. 复核记录随 Trace 保留，可修改，修改保留变更历史。
5. 盲审预留：设置中提供盲审开关（第一版默认关闭且不可启用）。开启后 Scorer 分数对复核者隐藏、判定顺序随机。多人模式与盲审的实际启用在后续版本实现。

**验收标准**：

- 在 Trace 详情标记存疑后，Review 队列出现该条记录。
- 完成一次复核，结果表与 Dashboards 能看到人工判定。
- 修改一次复核记录，变更历史保留两次记录。

### FR-7 闭环回流

**目标**：Loop-Assistant 归类失败原因、生成改进方案，帮助把有价值案例抽成新数据集。

**功能点**：

1. 触发入口：实验详情页对失败 Trace 集合发起 Loop-Assistant 分析。
2. 失败归类：对每条失败 Trace 输出失败原因类别与置信度。类别体系随使用累积（平台维护类别列表，允许新增）。
3. 改进方案：按失败类别汇总，生成改进方案报告。报告包含类别、典型案例、建议动作（改任务描述、改评分标准、改 Agent 配置、补数据）。
4. 案例抽取：从失败 Trace 中挑选有价值案例，生成新数据集草案（CSV 格式，字段与 FR-1 一致）。
5. 草案确认：用户可编辑草案行、剔除不需要的行，确认后合并进目标数据集产生新版本（变更说明自动引用来源实验）。
6. 分析记录：每次 Loop-Assistant 运行产出报告并归档，可在实验详情页回看。

**验收标准**：

- 对含失败任务的实验发起分析，产出失败归类与改进方案报告。
- 抽取案例生成草案，编辑确认后目标数据集产生新版本，版本说明包含来源实验编号。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 运行环境 | 单机本地运行，浏览器访问。Agent 与任务环境全部运行在本地 Docker 容器，执行仓库代码构建的镜像。外部依赖只有模型 API 与 Docker。 |
| 数据保留 | 平台元数据存 SQLite，单文件。评测产物沿用 Harbor 的 `jobs/` 目录，平台只存引用。 |
| 可重复性 | Experiment 快照完整记录复现一次实验所需的全部输入，事后可核对。 |
| 密钥安全 | 密钥继续只存 `.env`，平台不落库、不展示完整值（只显示末四位）。 |
| 性能 | 千行数据集的列表与筛选在 1 秒内响应。单实验百任务规模运行流畅。 |
| 视觉 | 与 Harbor view 风格一致，内嵌轨迹页无明显风格割裂。细节见开发文档设计规范。 |
| 兼容性 | 不修改 Harbor 编排代码与 Harbor view 读取逻辑。Harbor 升级不破坏平台。 |

## 6. 第一版边界

以下内容明确不做：

1. 多人账号、权限、任务分配。Review 为单人模式。
2. 盲审的实际启用（只保留设置项与数据结构）。
3. 分布式执行与多机调度。
4. 在线修改评测对象的 harness 镜像构建（镜像构建仍走 `scripts/build-harness.sh`）。
5. 数据集的数据库导入导出协议（只支持 CSV）。
6. 移动端适配。

## 7. 端到端验收场景

一条完整链路作为第一版发布门槛：

1. 创建数据集，上传 5 行 CSV，保存为版本 1。
2. 选择 pi harness 与一个模型，配置 LLM judge，用 `jobs/` 中已有的历史 Trace 试评通过并保存。
3. 新建实验，预检通过，一键运行，rollout 与 judge 全部完成。
4. 结果表查看分数，按分数升序找到低分任务，Trace 详情内嵌 Harbor view 查看轨迹。
5. 标记两条存疑 Trace，完成结构化复核。
6. 标记本实验为基线，修改数据集产生版本 2，运行第二个实验，对比页看到回归排序。
7. 对失败任务运行 Loop-Assistant，产出归类与改进报告，抽取案例生成草案，确认后数据集产生版本 3。
